# X1: vendored and generated code is out of scope by default

State: done, not committed. All items implemented with tests; measured on copies of the u18 trees.

## Causes confirmed on the code
- Probe: `Tree::walk` (dla-probe/scan.rs) skipped only build output, so `vendor/llhttp` made node and native runtimes. Census `list_files` already skipped `vendor` by name; the 729 aiohttp native candidates were five Cython `.c` files (generated), not vendor. grpc's 269 extra candidates were 27 files / 43 generated `*.pb.go`. Sweep's DLA rules had their own SKIP_DIRS (vendor, third_party), the external analyzers were filtered only by the user scope.
- Existing mechanism extended, not duplicated: the run scope in state.json plus `--include` stored in run state; one classifier `dla_core::vendored::Defaults`; `ToolCtx::static_scope()` is what static stages ask. Dynamic stages (summarize, correlate, harness copy, `ToolCtx::in_scope`) are untouched.

## Deviations (decided, in VERIFY)
1. aiohttp could not become python-only with the listed markers: `_find_header.c` says "The file is autogenerated from hdrs.py" and its `.h` has no marker. Added: the same sentence in other words, and a header next to a generated C/C++ file of the same stem. Also `_pb2_grpc.py`, `.pb.h`.
2. `external`/`extern` are left out only when not a package (`__init__.py`, Go `package <name>`, under a JVM source root).
3. Markers count only on comment lines in the first 20 lines, and mostly at the comment's start. Found and fixed by adversarial input: prose "Do not use @generated files" was a false positive.
4. A `.node` file under a left-out directory stays in the probe tree (boundary detection test `a_prebuilt_node_file_that_is_required_is_a_boundary` failed otherwise).
