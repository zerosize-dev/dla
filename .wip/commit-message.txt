Remove three chance failures of the dynamic acceptance; close the open check items

alloc-test
- The purge test uses the plateau test's minimum rise (32 KiB for a byte column): a growth
  at or below it since the warm-up reads no-growth, not retained. A few KB of live growth
  on a column that passed the first trend by chance no longer contradicts its plateau.
- The file-backed resident column still votes; only its purge reading is exempt when its
  plateau reads plateau (the purge step maps files itself). A leak of mapped files still
  reads leak.
- Python harness: on Linux every process loads ctypes and libc at start-up, and the trim
  purge reads its "before" value from the checkpoint's own reading. A flat run no longer reads
  "growth, retained" on resident memory because of the purge step's own imports.

Native summaries
- A capture's allocator shim record is chosen by identity, not by size. The harness
  writes the measured process's shim record only; the reader drops tool processes,
  prefers the process whose argv carries the iteration count, and falls back to size
  only with a limitation line that names the choice. Before, the record with the most
  live bytes won, and a project's test JVM that ran before the program could be read in
  its place at the first point, so the leak's stack was missing from capture 1.
- A run without --capture leaves the capture files of an earlier capturing run in place.
- dla-bench dynamic prints, for a refused label or confirmation, the reasons and
  limitation lines of each failed summary and the per-capture values of the holder its
  gate names, with the pid and last argv words of the record read.

- JVM warm-up test: it compares the rise of the warm run with the cold run's and measures
