Leave vendored and generated code out of scope; probes never import; one site, one finding

Found by running DLA on real libraries at versions with a documented leak.

Scope
- Vendored directories (vendor, third_party, node_modules, a git submodule, a virtual
  environment and the like) and generated source files (by the marker in their first
  lines) are not analysed by default: they do not count as a runtime of the project, are
  not swept, not in the census, not in workload discovery, not in the entry-point totals
  and not in the figures the time budget is sized from. On one Python library this takes
  the candidates from 922 to 187, the runtimes from three to one and the static stage from
  about five minutes to under one. A leak in such code that the project's workload
  triggers still shows as measured growth.
- The probe and the report name what was left out; `dla run init --include <path>` brings
  a path back.

Python harness
- A module probe reads a module only if the workload has loaded it and never imports one.
  A driver whose probes imported an example script that starts a server hung until its
  timeout; it now finishes, and the probe says the module was not loaded.
- A point killed at its timeout says what the agent was doing (start-up, a hook, a named
  probe).

Ledger
- A rule or analyzer hit and a census entry at the same site are one finding that carries
  both origins, the holder, owner, writers and removers of the census entry and the
  rule's message. For Python a decorator stack and its def line are one site.
- `dla harness gen --probe F<n>` for a finding without a probe target of its own answers
  with the reason and the finding to use; it no longer drops the request.
- What a rule's hit declares (holder, owner, region) wins over the census entry it joins,
  in either order of arrival; the census value goes into the note. The Go ticker rules and
  the Node timer rule declare the registered timer in the heap, so a joined ticker finding
  is not measured on the goroutine count.

alloc-test
- For a Go heap finding the exact exit column leads when the trend passed it and it rose
  by at least a tenth of what the in-run column rose by; otherwise the in-run column
  leads when it passed. The in-run reading is the noisier of the two and made a ticker
  leak read flat in about one run in four, and an exit column can pass on a kilobyte of
  its own while the state the finding holds is gone at exit.
