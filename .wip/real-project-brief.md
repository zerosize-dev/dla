## Why
DLA passes its 64 small benchmark fixtures, but on real projects it behaves badly. Measured on
real libraries at versions with a documented leak (trees under `<sp>/u18/<target>/proj`, each a
git repository with the `.dla/` of a static run; `<sp>/u18/<target>/log.txt`) and in one full
run of the skill on aiohttp 3.10.10 (`<sp>/u19/aiohttp`, its `.dla/`, and the run log
`<sp>/u19/aiohttp-run-log.md`):
- aiohttp: 922 static candidates, 733 of them from `vendor/llhttp` (a vendored C and Node
  project) and from C files generated by Cython. The probe therefore reported three runtimes
  (python, node, native), which makes the skill dispatch a worker per runtime, and the time
  budget was sized to 3 hours from those candidates. The native census alone took 250 s.
- grpc-go: 997 candidates, spring-data-commons: 623, Pillow: 655.
- The generated driver's module probes imported `examples/server_simple.py`, which starts a
  server at import: the harness run hung without a word until its timeout (580 s lost).
- The same site was listed twice, once by a DLA rule and once by the census
  (`aiohttp/web_app.py:82`: F8 and F102; `aiohttp/web_log.py:61`: F9 and F117), and a probe
  asked for the rule's finding (`--probe F8`) was dropped without a message.
